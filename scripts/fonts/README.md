# Web fonts

The site self-hosts subset fonts instead of `next/font/google`:

| Face                             | Where                                                                      | Files                     |
| -------------------------------- | -------------------------------------------------------------------------- | ------------------------- |
| Inter (variable, wght 400-900)   | every page (root layout)                                                   | `public/fonts/inter/`     |
| Anton                            | home, funnels, playbook, masterclass (`antonFont()` in `src/app/fonts.ts`) | `public/fonts/anton/`     |
| GeistBio (Geist 400/500/600/700) | `/mike`                                                                    | `public/fonts/geist-bio/` |

Each face has a **core** file, which is preloaded and holds ASCII, curly quotes, dashes, the ellipsis and every other character the site draws today. It also has an **extended** file holding the rest of Latin-1 and Latin Extended-A. The extended file sits behind `unicode-range` and only downloads on a page that uses one of its characters; no page does today. Every `unicode-range` lists exactly the code points its file contains.

Nothing here runs in the build. The files in `public/fonts/` and `src/fonts/` are generated by hand and committed.

## Rerun

Rerun when any of these happens:

- Content (a CMS page included) starts using a character outside the core: an accented name, `→`, `×`. It will still render, from the extended file. But a character served from a different file than its neighbours splits the word into two shaping runs, which can move the rest of the line by a sub-pixel. Rerunning moves the character into the core.
- A new weight, `font-variant-numeric`, `font-feature-settings` value, non-English `lang` attribute or `hyphens: auto` appears.
- A font source is upgraded (change the pinned URL and SHA-256 in `subset-fonts.py`).

```sh
python3 -m venv ~/.venvs/fonts && ~/.venvs/fonts/bin/pip install fonttools brotli uharfbuzz
npm run build && npx next start -p 3000          # current code + content
node scripts/fonts/audit-usage.mjs http://localhost:3000 > /tmp/font-usage.json
~/.venvs/fonts/bin/python scripts/fonts/subset-fonts.py --usage /tmp/font-usage.json
```

Leave out `--usage` to rebuild from the committed `usage-summary.json`. Output is deterministic: the same inputs give the same bytes and the same content-hashed file names. `/fonts/*` is served `immutable` (`next.config.ts`).

The script stops on any of these:

- a source whose SHA-256 doesn't match its pin
- a dropped code point
- surviving hinting tables
- output that isn't WOFF2
- any HarfBuzz difference (outline, advance, offset) between a built file and its source, per character, per ASCII pair, at every weight used plus one in between
- an OFL Reserved Font Name, which would require renaming a subset (none of the three fonts declares one)

## Prove it renders the same

Build the old and the new code against the same database. Run them side by side, then:

```sh
node scripts/fonts/pixel-diff.mjs http://localhost:3101 http://localhost:3102 /tmp/font-diff
```

This shoots each page twice on the old build and once on the new one, at desktop and mobile widths. It reports pixels that differ from both old shots. On `/` and `/mike` it also inserts a fixture block covering every Latin-1 and Extended-A letter, italics, bold inside italics, code, CJK, Cyrillic, Greek and Vietnamese.

## Choices that keep rendering identical

These were measured with pixel diffs on 2026-10-29:

- **Keep glyph names.** `post` format 3 saves about 600 B on Inter's core but changes anti-aliasing in Chrome on macOS.
- **Keep stored glyph bounding boxes** (`recalcBBoxes=False`). Geist's composites store an `xMin` that is one unit off their outlines, and rasterizers shift by `lsb - xMin`.
- **Pin Inter's `head` bbox** to the Google-served subsets it replaces. A recomputed bbox moved anti-aliasing by 1/255 on a few pixels per page.
- **Keep `calt`.** It costs about 4 KB on Inter's core (21.6 KB vs 17.6 KB), but it is on by default: it raises colons between digits, turns `->` into an arrow and adjusts hyphens between capitals.
- **Leave `locl` out.** It has no effect on `lang="en"`.
- **Cyrillic, Greek and Vietnamese are no longer served.** No page uses them; they fall back to the system font. CJK was never in these faces.

The fallback faces (`Inter Fallback`, `Anton Fallback`) and every `font-display` value are copied unchanged from what `next/font` generated.
