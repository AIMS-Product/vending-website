# Scripts inventory

Verified by reading each script on 2026-10-02 against `main` (`faac091`). Every script reads
`.env.local` (or the shell environment) and acts on **whatever that file points at**. A developer
`.env.local` normally holds the production Supabase URL and service-role key, so "writes
Supabase" below means **writes production unless you have pointed the file elsewhere**. Check
`NEXT_PUBLIC_SUPABASE_URL` before running anything marked WRITES.

## How to read the table

- **Writes**: which external system changes. `none` means no external system is changed.
- **Safe default**: what protects you. `dry run` means the script does nothing unless a flag
  such as `--apply` or `--write` is passed. `NONE` means it acts the moment it runs.
- **Status**: `recurring` (a tool to keep), `one-off` (finished repair or import, kept as
  evidence and as a template), `test` (smoke or QA check).
- `scripts/lib/launch-check-helpers.mjs` is a shared helper for the launch checks. `*.test.mjs` files next to a script are Vitest tests (`vitest.config.ts` includes
  `scripts/**/*.test.mjs`) and run with `npm test`.

## Rules for new scripts

1. Dry run by default; require an explicit flag (`--apply`, `--write`) to change anything.
2. Print the target Supabase host and project before writing.
3. Snapshot rows to a local file before deleting or overwriting them.
4. Never print secrets. Never hard-code credentials, including "public" keys, in a script.
5. Add the script to this table in the same commit, with its writes and safe default.

Known gap: `merge-objection-library-tags.mjs` embeds a publishable (read-only) key for a separate
Supabase project, the Objection Library. It is not a secret, but it breaks rule 4 and should
move to an environment variable.
