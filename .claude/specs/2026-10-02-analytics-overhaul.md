## 7. Decisions taken (Adam: "continue with your best recommendations", 2026-10-02)

- **D1 → America/New_York**, not Pacific: it is the zone the code already names `REPORTING_TIME_ZONE` (booked-call measures), so the dashboard adds no fourth day boundary. METRICS §1 row added.
- **D2 → cohort flow**, won read from Close opportunities dated from the window start (furthest stage reached), not current status. METRICS §16.
- **D3 → KPI Leads = site leads (people)**; the flow's first stage is Captured (leads + contacts).
- **D4 → §10 CAC for the newest month with typed inputs**, labelled with its month and "October not entered yet". No new CAC definition.
- **D5 → `/admin` redirects to `/admin/analytics`.**
- Chatbot has no band: Close files chat-booked calls under the arrival funnel (13 of 18 = Website), so chatbot captures sit in Website & search.
- Setter split uses Close's setter field (§12 rule 5) over the same calls, so its total matches the card; the full credit chain stays on /admin/bookings (its population includes onboarding and follow-ups).
- No sync code fix was possible: Bitly and ManyChat need credentials/setup; the `_____` UTM is a Calendly link template outside this repo (351 bookings, all-time).
